# 📜 每月新规 · 下个月起这些规定要变了

> 每个月 1 日前后都有一批新规开始施行。这个页面把即将施行的法律法规、强制性国家标准，以及新闻里的社保、个税、房贷、交通、教育等政策汇总在一起，按月份和类别查看

**🌐 在线访问：[https://climb0516.github.io/new-rules/](https://climb0516.github.io/new-rules/)**

---

## 功能

- **按施行月份查看**：下月起、本月、更远、上月（回顾）；每个月顶部显示全国新规条数、最受关注的一条、距 1 日还有几天
- **分类筛选**：社保医保、收入个税、交通出行、消费购物、住房物业、教育育儿、就业劳动、金融投资、医疗健康、食品药品、三农、网络数据、安全应急、生态环境、出入境（按关键词自动分类，一条可以属于多个类别）
- **类型筛选**：法规（官方数据库）/ 新闻 / 国标；技术类强制性国标（检测设备、工业产品等）默认折叠
- **地区**：默认只看全国；可以选「全国 + 某省」，或者看全部地区。选择记在本地浏览器
- **合并报道**：同一条新规的多篇新闻合并成一条，报道数 ≥ 3 的标 🔥；新闻里提到的法规名能对上官方条目时，报道挂到官方条目下
- **配图**：每条新规从报道原文里取一张配图（`og:image` / 正文首图），列表右侧显示缩略图，月份顶部用封面卡展示最受关注的 4 条
- **每月盘点**：媒体每月末发的「X 月起这些新规将影响你我生活」
- 全文搜索（`⌘K` / `Ctrl K`），右上角：↻ 重新读取数据，⚡ 跳转 GitHub Actions 手动触发抓取，☾ 切换深浅色；手机适配

## 技术架构

```
GitHub Actions（定时：每天北京时间 07:30 / 手动 dispatch / push 修改 scraper.py 或 workflow）
  ↓ python scraper.py（Python 3.12，只用标准库，无需安装依赖）
  ↓ 3 个线程并发抓取：
  ↓   ├ laws()       国家法律法规数据库 接口
  ↓   ├ standards()  国家标准全文公开系统 网页解析
  ↓   └ news()       Google 新闻 RSS + Bing 新闻 RSS → cluster() 合并同一条新规
  ↓ merge()   新闻按法规名挂到官方条目上
  ↓ details() 补抓法规历史版本 / 相关资料、国标分类号 / 主管部门（增量，最多 90 秒）
  ↓ covers()  从报道原文取配图（增量，最多 150 秒）
  ↓ 写入 data.json（与上一份合并），git commit + push
       ↓
GitHub Pages（index.html）
  ↓ 前端 fetch 同目录 data.json（cache: no-cache）
  ↓ 按施行月份 / 类型 / 分类 / 地区渲染列表
  ↓ kit 详情抽屉（#/item/rule/…、#/item/roundup/…）+ 列表页（#/list/month/…、later、roundup）
```

- 某个来源本次抓取失败（`run()` 捕获异常）时沿用上一份 `data.json` 里该类、仍在时间窗内的条目，`sources.<类>.stale = true`，右侧「来源状态」显示「旧数据」
- 详情字段、配图任一步出错只打印日志，不影响主数据写入

## 数据来源

| 来源 | 方式 | 每次条数 / 范围 | 备注 |
|---|---|---|---|
| [国家法律法规数据库](https://flk.npc.gov.cn/) | 接口：POST `/law-search/search/list` | `FLK_PAGES = 6` 页 × 每页 50 = 最多 300 部，再筛施行日期在时间窗内的 | 法律、行政法规、地方法规、自治条例等；带公布日期 `gbrq`、施行日期 `sxrq`、制定机关；跳过「修改、废止的决定」 |
| 法律法规数据库详情 | 接口：GET `/law-search/search/flfgDetails?bbbs=…` | 仅新条目，预算 `DETAIL_BUDGET = 90` 秒，6 线程 | 历史版本 `lsyg`、相关资料 `xgzl`（公告、批准决定、草案说明等） |
| [国家标准全文公开系统](https://openstd.samr.gov.cn/) | 网页解析：`std_list`（`p.p1=1` 强制性国标，按 `circulation_date` 倒序） | `STD_PAGES = 3` 页 × 每页 50 = 最多 150 条，再筛实施日期 | 取标准号、名称、是否采标、状态、发布 / 实施日期 |
| 国标详情页 | 网页解析：`newGbInfo?hcno=…` | 与法规详情共用 90 秒预算 | 英文名、CCS / ICS 分类号、主管部门、归口部门、发布单位、备注（`STD_FIELDS`） |
| Google 新闻 RSS | RSS（`hl=zh-CN&gl=CN`） | 5 个关键词 × 2 个月份 = 10 次查询；每次返回条数不限定（未确认具体数量），只收 `NEWS_DAYS = 45` 天内发布的 | 部门规章、政策通知主要靠新闻；标题去掉「 - 来源」尾巴 |
| Bing 新闻 RSS | RSS（`format=rss&setlang=zh-cn`） | 同上，10 次查询 | 从跳转链接里取出原文 `url`；带摘要 `description` |
| 报道原文页 | 网页解析（`og:image` / `twitter:image` / 正文 `<img>`） | 预算 `COVER_BUDGET = 150` 秒，4 线程，每条每次最多试 `COVER_TRIES = 3` 篇 | Google 新闻链接先经 `batchexecute` 接口（`gnews_real()`）换出原文地址 |

**新闻搜索词**：`NEWS_QUERIES = ["{m}月1日起施行", "{m}月1日起实施", "{m}月起 新规", "{m}月起 这些新规", "{m}月1日起 正式实施"]`，`{m}` 依次填本月和下月。增删搜索词直接改这个列表。

**增删来源**：
- 调整抓取深度：改 `FLK_PAGES`、`STD_PAGES`、`NEWS_DAYS`
- 新增一类来源：写一个返回条目列表的函数（字段同下方「数据结构」），在 `main()` 里用 `ex.submit(run, "名称", fn)` 加进去并放入 `res`，再在 `index.html` 的 `SRC_NAME`、`KIND` 里补显示名和颜色
- 删除来源：从 `main()` 的 `res` 里去掉对应项

**限制**：
- 法律法规数据库不收部门规章（社保、个税、车险等多是部门规章或政策文件），这类只能从新闻里拿到，日期按标题提取，以官方原文为准
- 新闻条目的「全国 / 地方」按标题里的省市名判断，可能误判；分类标签按关键词匹配，仅供筛选
- 国外和跨境电商的新规会过滤掉
- 配图是外链图片，页面设了 `referrerpolicy="no-referrer"`（腾讯、澎湃等图床校验 Referer）；图片加载失败时前端 `dropImg()` 自动去掉

## 数据处理规则

**时间窗**（`in_window()`）：只收施行日期在 `KEEP_FROM`（上个月 1 日）到 `HORIZON`（今天 + 400 天）之间的条目。例：今天 11 月 5 日 → 保留 10 月 1 日起施行的，超出窗口的旧条目在下次运行时自动移除。

**施行日期提取**（`effective_date()`，新闻用）：
- 正则 `EFF_RE` 匹配「(2026 年)11 月(1 日)(起)(正式 / 全面)施行 / 实施 / 执行 / 落地 / 生效 / 实行」，没写日默认 1 日
- 没写年份时按报道发布日期推断；推出来的日期比发布日期早 200 天以上就算明年（12 月发的「1 月起施行」→ 明年 1 月）
- 先从标题提取，提取不到再看摘要

**新闻过滤**（`news()`）：
- 发布时间早于 45 天前的丢弃
- 标题或摘要前 60 字命中 `FOREIGN`（美国、欧盟、日本……亚马逊、TikTok Shop、Temu、海外仓等）的丢弃
- Bing 摘要和标题共享的核心二字片段少于 2 个（`relevant()`）视为配错，清空摘要
- 标题命中 `ROUNDUP_RE`（如「11 月起这些新规」「一批新规」）且月份是本月或下月的，归为「每月盘点」，按标准化标题前 20 字去重，`OFFICIAL` 匹配到新华、央视、人民等来源的标 `official`，最多保留 30 篇

**新闻去重与合并**：
1. 条目 id：标题或摘要里有《法规名》（4～60 字）时为 `news-<法规名标准化>`，否则 `news-<标题标准化前 24 字>`；同 id 的报道追加到 `articles`
2. 新闻条目跨次运行累积：上一份 `data.json` 里的新闻条目作为基础，本次新抓的合并进去
3. `cluster()`：同一施行日期下，满足任一条件合并为一条——法规名互相包含；一方的法规名出现在另一方标题里；标题切成小句（`clauses()`，去掉「新规 / 施行 / 来了 / 划重点」等套话 `STOP`）后，某两句完全相同或共享 ≥ 2 个二字片段且占较短一句的 ≥ 50%（`similar()`）
4. 合并后标题取各报道标题里（去掉「|标签」「_新浪网」尾巴，`clean_title()`）含法规名且长度最接近 26 字的一篇；任一篇按全国报道，整条就算全国；每条最多保留最新 6 篇报道
5. `merge()`：新闻的法规名标准化后与法律法规数据库标题完全一致时，把报道、摘要、标签挂到官方条目上，不再单列
6. 最终排序：施行日期 → 法规优先 → 标题

**分类标签**（`tags_of()`）：`TAGS` 里 15 个类别各一条关键词正则，命中即打标签，可多个。例：「医保 / 养老金 / 退休」→ 社保医保，「电动自行车 / 驾照 / 网约车」→ 交通出行，「个人信息 / 算法 / 手机号」→ 网络数据。新增类别直接在 `TAGS` 里加一行（前端 `CAT` 里补图标和颜色）。

**地区判断**（`region_of()`）：
- 标题里出现省名（`PROVINCES`）或地级市名（`CITY2PROV`，约 300 个市州映射到省）时，取最早出现的那个对应的省
- 都没有时：标题 + 摘要前 120 字命中国务院、财政部、人社部、强制性国家标准等国家级机关（`NATIONAL`）的算全国（`region = ""`）
- 仍不确定但匹配「XX 市 / 州 / 县 / 盟、本市、全省」等（`LOCAL_RE`）的记为「其他地方」
- 法律法规：只有地方法规、自治条例、单行条例、经济特区法规才判断地区，优先按制定机关，其次按标题

**配图**（`covers()`）：
- 上次已有图的沿用；国标不配图；按「下月施行优先 → 未施行优先 → 报道多的优先」排队
- 每篇报道取 `og:image` / `twitter:image` / 正文前 40 个 `<img>`，最多 6 个候选；`http://` 改成 `https://`
- 过滤（`bad_img()`）：URL 含 logo、icon、qrcode、share、default、banner、wechat、`.svg`、`.gif` 等；路径里带着前年以前日期（如 `2023/05`）的多半是站点默认图
- 校验（`good_img()`）：不带 Referer 能下载，从文件头读宽高（`img_size()`，支持 PNG / GIF / WebP / JPEG），宽 ≥ 360、高 ≥ 160、宽高比 1.2～2.6
- 试过的报道 URL 取 SHA1 前 8 位（`h8()`）记在 `cover_tried`，下次不再重复抓；网络失败的不记录，下次再试
- 同一张图出自两篇以上不同文章的，判为站点默认分享图，全部去掉

## 前端

**kit 详情抽屉**：点任一条目在站内打开详情，电脑上从右侧滑出，手机上从底部升起；地址同步写成 hash，可以直接分享，打开分享链接时数据读完后由 `KIT.boot()` 直接弹出详情；对应条目已下榜、过期或被合并时，弹出「这条内容已不在当前数据里」的提示和「回到首页」按钮。浏览器返回即关闭抽屉。

| 条目类型 | 地址 | 内容 |
|---|---|---|
| `rule` | `#/item/rule/<encodeURIComponent(id)>` | 基本信息（类型、施行 / 发布日期、制定机关、地区、标签、国标分类号与主管部门）、英文名称、摘要、历史版本、相关资料、全部报道、同分类的其它新规；按钮「查看原文 / 阅读报道」「配图出处」 |
| `roundup` | `#/item/roundup/<链接短哈希 hid(url)>` | 说明、该月起施行最受关注的 6 条全国新规、同月的其它盘点；按钮「阅读原文」 |

| 列表 key | 地址 | 说明 |
|---|---|---|
| `month` | `#/list/month/<YYYY-MM>` | 某月起施行的全部新规（首页每个月份只显示前 10 条，`HOME_N = 10`） |
| `later` | `#/list/later` | 下下月及以后施行的，按月分组 |
| `roundup` | `#/list/roundup`、`#/list/roundup?official=1` | 每月盘点文章，可只看官方媒体 |

列表页支持 query 参数 `kind`（law / news / std）、`tag`（分类）、`sort`（`date` 按施行日期 / `heat` 按关注度 / `pub` 按发布日期），每页 30 条，「加载更多」追加。

**本项目特有**：
- 侧栏视图：下月起、本月、更远、上月（回顾）、每月盘点
- 关注度 `heat()` = 报道篇数，全国性法规额外 +3；用于封面卡、右栏「近期最受关注」和按关注度排序
- 月份顶部 4 张封面卡：按分类画渐变 + 图标（`CAT`），不用新闻图；列表行右侧显示 `img` 缩略图
- 国标大多是技术标准：没有分类标签的国标只在「国标」类型下出现（`shown()`）
- 地区：只看全国 / 全国 + 某省 / 全部地区；类型、地区、深浅色记在 `localStorage`（`nr:kind`、`nr:region`、`nr:theme`）
- 搜索：`⌘K` / `Ctrl K` 聚焦，`Esc` 清空，匹配标题、法规名、机关、摘要、地区、标签
- 右栏「来源状态」显示每个来源的条数 / 旧数据 / 失败
- 右上角 ↻ 重新读取 `data.json`，⚡ 跳转 GitHub Actions 手动触发抓取，☾ 切换深浅色
- 以前的「精选解读」（读 `picks.json`，在月份顶部显示是什么 / 影响谁 / 要做什么）在 2026-10-22 改成详情抽屉时去掉了，现在每条新规的解读在详情抽屉里看

## 本地运行

```
python3 scraper.py            # 只用标准库，无需 pip install，无需环境变量
python3 -m http.server        # 浏览器打开 http://localhost:8000
```

- CI 使用 Python 3.12；本地最低 Python 版本未确认，建议同用 3.12
- 运行时会读取已有 `data.json` 做增量（新闻累积、详情 / 配图沿用），首次运行没有它也可以，但配图和详情需要多跑几次才会补全
- 一次完整运行至少包括详情 90 秒、配图 150 秒的预算上限

## 自动更新机制

| 触发方式 | 时机 |
|---|---|
| GitHub Actions 定时任务 | 每天 07:30 北京时间（cron `30 23 * * *`，UTC 23:30） |
| push 到 main 分支 | 仅当修改了 `scraper.py` 或 `.github/workflows/scrape.yml` |
| GitHub Actions 手动 dispatch | 按需触发（页面右上角 ⚡ 直达） |

- 同一时间只跑一个任务（`concurrency: scrape`，不取消排队中的任务）
- 运行完提交 `data.json`，提交信息 `data: update <北京时间>`，提交者 `github-actions[bot]`
- 心跳：`data.json` 的 `updated` 字段每次运行都会变化，所以每次运行都会产生一次提交，前端顶部显示「更新于 X 分钟前」
- GitHub 会在仓库 60 天无提交时自动停用定时任务；本项目靠每天的数据提交保持活跃。若定时任务连续失败导致长期没有提交而被停用，需要到 Actions 页面重新启用
